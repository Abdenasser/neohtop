Install the free NeoHtop desktop system monitor on macOS, Windows, or Linux. Official binaries are published on GitHub Releases.

NeoHtop v1.3.0

Downloads refer to the latest published release. Version 1.3.0 includes the desktop refresh, process families, GPU diagnostics and menu-bar overview. Older versions differ. Pro is postponed and is not part of these downloads.

Install NeoHtop on macOS

  1. Open the latest published release.
  2. Choose the Apple Silicon DMG for M-series Macs or the Intel DMG for Intel-based Macs. In Apple menu → About This Mac, look for “Chip” or “Processor.”
  3. Open the DMG and drag NeoHtop into Applications.
  4. Launch NeoHtop from Applications.

Homebrew alternative

The community-maintained Homebrew cask offers another install path. Its version and update timing can differ from the official releases.

$brew install --cask neohtop

If macOS cannot verify a download, confirm you obtained it from the official repository and read the release notes. Do not disable Gatekeeper or remove quarantine flags as a routine install step.

Install NeoHtop on Windows

  1. Find the Windows x64 .exe in the latest release assets.
  2. If its name ends in -setup.exe, run the installer and follow its prompts.
  3. Older published releases may provide a portable .exe. Put that file in a folder you control and launch it there.

Use a package listed for your architecture. Consult the release notes for platform requirements and known issues.

Install NeoHtop on Linux

Choose the package for your distribution and CPU architecture. Run uname -m: x86_64 means x64, and aarch64 means ARM64. An architecture may be unavailable in older releases.

Linux package options
Package Use it for Install approach
.deb Debian / Ubuntu Open it in your system’s package installer, or install the downloaded local file with apt.
.rpm Fedora and compatible RPM distributions Use your distribution’s package manager to install the downloaded local file.
AppImage A portable Linux app Make the downloaded file executable in its Properties, then open it.

AppImages still rely on system libraries and may require FUSE support. “Portable” does not mean compatible with every distribution or glibc version.

Troubleshooting

A Linux build reports a glibc error or opens a blank window

First check the release notes and your distribution version. Version 1.3.0 builds on Ubuntu 22.04 and checks AppImages for bundled host Wayland libraries. Older releases may not contain these fixes. Try an appropriate native package if available, and include the exact error when reporting a problem.

Some process details are missing

Operating-system permissions can restrict which details are visible. See the repository’s platform-specific guidance before granting elevated access. Normal use should start without administrator privileges.

Need help?

Open a GitHub issue with your NeoHtop version, operating system, architecture, package type, error text, and steps to reproduce. Redact credentials and private command-line arguments from diagnostic output.

Build the development version

Developers can build the current source with Node.js 22, stable Rust 1.88 or newer, and the platform prerequisites for Tauri. This is a development build and may differ from the published app. 

git clone https://github.com/Abdenasser/neohtop.git
cd neohtop
npm ci
npm run tauri dev

Read the repository’s development instructions for platform setup and build commands.
